# DESIGN

## 設計方針

- 深い継承より、Node、Scene、Resource、Signalを使ったコンポジションを優先する。
- 再利用可能なSceneは、可能な限り外部のシーン構造に依存せず単独で動作できるようにする。
- 各ScriptとSceneには、明確に説明できる一つの主要な責務を持たせる。
- 責務とライフサイクルを説明できないManager、Service、Controller、Utilityクラスを追加しない。

## 依存関係

- 複数のNodeの関係を把握している所有者が、依存関係の設定やSignalの接続を担当する。
- 外部依存は、`@export`、公開プロパティ、初期化メソッド、Callable、Resourceなどを使用して明示的に提供する。
- 外部依存を取得するためにSceneTree全体を探索する実装は避ける。

## 継承

- 直接インスタンス化しない基底クラス、派生クラスで実装必須のメソッドではメソッドには `@abstract` をつけること

## Godotの構成要素

### Scene

- 再利用可能な Scene は、可能な範囲で自己完結させる。
- Scene 内部の Node 構造は実装詳細として扱う。
- Scene 外部からの操作は、Scene Root または明確な公開APIを通して行う。
- SceneTree は、表示上の階層だけでなく、所有関係とライフサイクルを考慮して構成する。
